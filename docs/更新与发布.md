# 更新与发布

更新来源为[SeXon007/ChatBubble](https://github.com/SeXon007/ChatBubble)的正式GitHub Releases。便携发布不使用安装器专用的Electron内置更新器；具体接口见[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)及[Electron更新机制](https://www.electronjs.org/docs/latest/api/auto-updater)。

## 用户更新

设置→版本→检查更新。只有明确点击才联网，不发送聊天、模型密钥或CLI凭据，也不在软件中嵌入GitHub Token。正式版本号须为`v主版本.功能版本.修复版本`，草稿、预发布及不高于当前版本不用于升级。

发现新版后点击更新，下载相应Windows x64 ZIP并核对GitHub资产的SHA-256、大小和地址。下载到应用数据目录内的独立临时目录，失败不执行文件。随后在旧版同级目录准备新版，拒绝覆盖已有目录、路径越界、符号链接、重复路径及包含聊天数据的发布包。目标父目录需可写，准备失败保留当前应用。

准备完成点击“重启并更新”；若正在生成/保存，先完成当前操作。聊天和设置保存失败时取消退出。助手等待旧进程正常退出，再启动新版；不杀死用户进程，不迁移或覆盖chat，不改凭据。只更新已知且目标恰为旧版EXE的快捷方式；未识别的自建快捷方式需手动改目标。启动后短时间退出会触发恢复原快捷方式并尝试启动旧版。

0.13.x没有更新模块，首次需手动解压运行0.14.1。之后可使用内置更新。旧版包可用于回退；切勿删除仍被聊天记录引用的attachments。

## 发布者流程

1. 更新package.json及package-lock.json版本，维护CHANGELOG.md和RELEASE_NOTES.md；修复递增末位，功能/UI递增中间位并清零末位，重大更新按项目约定递增首位。
2. `npm ci`、`npm test`，并对关键改动执行相应隔离界面/原生检查；不得把模拟服务当作真实账户验证。
3. `npm run package`；已有同版本目录会拒绝覆盖。检查包内chat为空，没有Key或个人记录。
4. PowerShell运行`./scripts/release-zip.ps1 -Version 0.14.1`（版本按实际修改）。生成完整便携ZIP和SHA256SUMS.txt；ZIP不包含chat目录。应用MIT许可证位于LICENSE.ChatBubble.txt，Electron/Chromium原许可证保留。
5. 提交审查后的源码并创建与package版本相同的`v版本号`标签。标签推送触发Windows测试、打包、上传构建产物并创建草稿Release；普通main提交只运行Windows测试。工作流手动运行只生成构建产物。
6. 核对草稿资产、说明、校验值和版本，再将其发布为正式Release。草稿不影响用户更新；正式发布后才会被软件检测。避免覆盖已经正式发布的版本资产，修复发布新版本。

源码仓库忽略本地chat、凭据、node_modules、dist、release以及内部验证备份/原型；发布资产仅为干净ZIP和校验文本。不要将完整工作目录打包上传。

## 验证与限制

离线测试覆盖版本/资产验证、流式下载校验、取消、非法压缩路径、旧版数据保留以及自建原生程序启动/失败回退。隔离Electron检查覆盖真实版本页、预加载及生产IPC。真实GitHub发布检查和资产核对以发布时记录为准；这些证据不能替代所有电脑、代理、权限条件下的长期更新体验。更新包当前未签名，信任来源是该公开仓库及GitHub HTTPS，SHA-256用于核对内容一致性，不等同于独立代码签名。
